Per-Bot DeepSeek — stay on cursor

Default is Grok 4.6. Assigned UUIDs hop to api.deepseek.com using
~/sand-data/deepseek.env (DEEPSEEK_API_KEY=...). Unassigned Bots get a
raw Cursor session (no Proxy). Live id is lazy conv= at create
(where=store) or where=none — or where=stream when id arrives late.

Do NOT:
  ./adapters use deepseek
  ./adapters recover
  ./adapters restart-host
  Update Grok Bot's Computer          (that is RECOVER, not apply)
  supervisor forceNow upgrade bounce  (twice took down the fleet)
  python3 brain-install-bundle.py
  hand-edit the ~25MB host-main.cjs
  claim "Quit Grok Bot and reopen" loads patched host-main
    (desktop quit drops the client only; host-main is always-on under
     /usr/local/bin/sand-supervisor.mjs)

Truth about load on this computer:
  - Host process: node /home/box/sand-host/host-main.cjs via sand-supervisor.
  - Stock launchHost() spawns HOST_ENTRY immediately — no prestart, no
    sand-data hook, no NODE_OPTIONS.
  - Wrap on disk is inert until a host process START already has the wrap.
  - agent-data -> sand-data (symlink).

Attach (Grok already chats; provider is cursor):

  1. Copy from Explorer (DURABLE under sand-data / agent-data —
     sand-host is wiped on Computer recover / boot-fetch):
       tools/brain-router.cjs                 -> ~/sand-data/brain-router.cjs
       tools/patch-brain-hook.py              -> ~/sand-data/patch-brain-hook.py
       tools/ensure-brain-overlay.py          -> ~/sand-data/ensure-brain-overlay.py
       tools/host-prestart-ensure.sh          -> ~/sand-data/host-prestart-ensure.sh
       tools/install-supervisor-prestart.py   -> ~/sand-data/install-supervisor-prestart.py
       tools/brain-assign.py                  -> ~/sand-data/brain-assign.py

  2. printf 'DEEPSEEK_API_KEY=sk-...\n' > ~/sand-data/deepseek.env
     chmod 600 ~/sand-data/deepseek.env

  3. Disk wrap (idempotent; FULL-file node --check; restore on failure):
       python3 ~/sand-data/ensure-brain-overlay.py

  4. Wire supervisor so the NEXT launchHost re-applies before spawn

     Live sand-supervisor.mjs is ESM root-owned under /usr/local/bin —

     re-execs via `sudo -n` with absolute --sand/--tools (sudo sets HOME=/root).
       python3 /home/box/sand-data/install-supervisor-prestart.py \
         --sand /home/box/sand-data --tools /home/box/sand-data
     Does not bounce. Does not Update Computer.

  5. Wrap becomes live only after a host process start that goes through
     the patched launchHost (or otherwise starts a host-main that already
     has the wrap on disk). Do not forceNow / restart-host to force that.

  6. grep -F '[sand-brain]' /tmp/sand-host-manual.log | tail -n 8
     Want brain=grok and where=none|store|stream. Dashboard must not move.

  7. After a Bot intros: python3 ~/sand-data/brain-assign.py on <uuid>
     Next createSession with that id hops. Another Bot stays grok.

After boot-fetch (sand-host swapped, supervisor binary KEPT):
  If launchHost was patched, it runs ensure before spawn → wrap can return
  without hand-editing host-main and without forceNow.

After Update Computer (image recover):
  Supervisor is reset from the image → prestart patch is GONE.
  Durable brain-router + bindings + ensure scripts under sand-data SURVIVE.
  The wrap does NOT auto-come back. With the current Cursor supervisor there
  is no durable automatic hook between image restore and first spawn.
  Honest post-recover sequence (still no bounce as "apply"):
    python3 ~/sand-data/ensure-brain-overlay.py
    python3 ~/sand-data/install-supervisor-prestart.py
  Then the wrap is on disk + supervisor is wired; it goes live on the next
  host process start through launchHost — not via desktop quit.

Daily (no restart):
  python3 ~/sand-data/brain-assign.py on|off <UUID>
  python3 ~/sand-data/brain-assign.py list

Clone = new UUID; on again.
